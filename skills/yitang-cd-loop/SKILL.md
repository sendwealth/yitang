# C×D 实战循环:业务公式 × 转化率

> **增长问题 = 业务公式(C,定方向/优先级/因果)× 转化率(D,轰假设/单点突破)。**
> D 打不动 → 退回 C 重新找参数 → C 找到关键参数 → 回 D 继续打穿。

| 维度 | 业务公式(C) | 转化率(D) |
|---|---|---|
| 解决什么 | 全局:哪个参数空间最大、谁是突破口 | 具体节点:怎么轰假设、单点击穿 |
| 语言 | 方向、优先级、因果 | **动力、阻力、触点** |
| 作用 | 找战场 | 打节点 |

## 转化率三要素(打节点的通用语言)

- **动力**:用户为什么想要?(名·权·情 往往比返钱更有效)
- **阻力**:什么让他卡住/放弃?(步骤多、贵、怕、麻烦)
- **触点**:哪个时刻/位置能触到他?(创造推荐触点,如"先体验后付款")

任何转化问题都用这三要素拆,代替"这顾客就是喜欢/嫌贵"这类归因。

## 关键教训(真实案例提炼)

0. **没数据,没法提假设**:动手前先确认该节点有分子/分母数据;线下无数据时先设计低成本采集(如专人数人头)拿到基线,再提假设。
1. **打不动往往是因为打错了战场**:窗口期狂轰动力/阻力/触点只是止跌——退回业务公式才发现真问题是"平日积累×窗口期激活"的平日端。
2. **别把相关当因果**:"作业率与续班率正相关"≠做作业导致续班(可能是"孩子本来就喜欢"的中间变量)。
3. **同名指标≠同指标**:新客办卡率(即时转化)与回流办卡率(二次邀约)路径完全不同,必须拆开经营;一个门店业务可拆出 40+ 细分参数。
4. **扩张改变参数构成**:整体续班率 = Σ wᵢ·rᵢ(新生/老生 × 新老师/老老师 分层加权)——扩张改变的不仅是量,还有公式里参数的权重。
5. **链路型转化是乘法关系**:裂变 = 信任转移×体验承接×独立转化×反馈闭环,任一环节为 0 则整体归零;只优化单一转化率而后端接不住可能白做(案例:送水把进店率轰到 100%,总销售额却没变)。

## 操作步骤

1. 用 `yitang-business-formula` 拆出当前公式与分层参数。
2. 选定要打的节点,列出该节点上的动力清单、阻力清单、触点清单。
3. 为每一项提一个低成本可验证的假设(例:礼品卡标注价值 288 元+情感文案,能否提升回流率)。
4. 单点实验,看数据,复盘(示例:礼品卡标注价值 288 元+情感文案→回流率从 1% 提升至 5%→10%+)。
5. **若连续两轮打不动,停止加码,退回 C**:是不是节点太靠后/太粗?是不是全局最该打的战场在别处?
6. 打穿的节点沉淀为 SOP,让团队照做(新人 60 分,老人迭代 80-90 分)。

## 科学型组织四步(把个人经验变成组织能力)

1. 统一语言:全员用"动力/阻力/触点"代替主观归因。
2. 个人经验→团队经验:每人用同一框架写真实案例复盘。
3. 沉淀 SOP:点状经验→标准动作。
4. 最佳实践手册:案例输入→复盘共性→提炼→新人能学/老人能查。
