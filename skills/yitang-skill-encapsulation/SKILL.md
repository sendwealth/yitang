# Skill 封装五阶段

> **经验不只存在脑子里,也可以成为 AI 的能力。** 大白话三件事:①找一件值得反复做的事 → ②做好一遍,把方法写下来 → ③换份材料再用一次。
> 核心:**封装 Skill 本质上不是把提示词写长,而是把判断讲清。**

```
① 明确场景与目标 → ② 先把一次任务做好(V0) → ③ 提炼六类规则
→ ④ 封装成能调用的 Skill(V1) → ⑤ 换份材料验证(V2)
```

## ① 明确场景与目标

- 列 3-5 个「名称/频率/麻烦点」的场景清单。**只用一两次的任务,不必为了封装而封装。**
- 选题四判据:重复频率、实际价值、材料是否够用、能否判断好坏。
- 写下 3 条可逐项核对的合格标准 + 一句话目标公式:**当【谁】遇到【场景】时,使用【输入】,按【方法】,产出【结果】。**

## ② 先把一次任务做好(V0)

和 AI 一起做出一份你认可的结果,并留下纠正过程:AI 第一版哪里不对(原话+你的纠正)、改到什么程度才愿意用、下次还会用到的提醒。完成标志:**能对照原材料解释为什么合格**,而不只是"看起来不错"。

## ③ 提炼六类规则(AI 提炼只是初稿,必须逐条确认)

| 规则 | 关键问题 |
|---|---|
| ① 场景 | 什么时候用 / 不用 |
| ② 输入 | 必需什么,缺了怎么办 |
| ③ 步骤 | 做法拆成哪些动作 |
| ④ 标准 | 怎么判断做得好(**含正反例**) |
| ⑤ 边界 | 缺信息/冲突/超范围怎么办 |
| ⑥ 输出 | 固定交付什么 |

纪律:每条规则注明来源;只保留能用于同类新任务的做法;**不把本次人名、日期写成固定规则**;没依据的标"待确认"。

## ④ 封装成能调用的 V1

规则要**离开旧对话也能被完整读取和使用**:正文=六类规则+一条调用示例,别人无需翻历史聊天就能开始;较长正反例放 references,固定模板放 assets。两个反直觉提醒:**保存了文件 ≠ 工具已经加载;只说技能名称 ≠ AI 能看到规则。**

## ⑤ 换份材料验证(三类测试)

新建对话重新调用(不口头补充方法):

1. **正常任务**:换一份信息完整的新材料,看输出是否符合预期;
2. **信息不足**:删掉一项关键输入,看它是先索要原文而不是编造;
3. **边界任务**:给一个相近但不适用的请求,看它是否说明超出范围。

发现问题→**一次只改一类**→三重复测(原失败案例+正常回测+新输入)。没有问题时保留 V1 并如实记录,不硬凑修改;没实际运行的测试标"待测试",**不编造通过结果**。

## 三个诚实完成标准

能解释为什么选这个场景(而不是"AI 推荐的");能讲清自己的封装方法(六类规则里哪些是自己补充/删除/改写的判断);在新对话中用新材料调用成品成功。**不把"生成了一段提示词"当作完成。**

## 写 SKILL.md 的架构要点(配套)

好 Skill 是可执行程序,不是知识:每条原则必须配反例(没反例是"注意一下",有反例是"上次翻车了");流程层要有检查点——对执行 AI 无效的注意事项,必须编译成流程里的强制等待/确认节点;冲突时给编号定优先级。
